=== Q2 calculations ===
== Page-table size (4 KB pages, single-level table) ==
32-bit: 1048576 entries x 4 B  = 4194304 bytes = 4.0 MB per process
48-bit: 68719476736 entries x 8 B  = 549755813888 bytes = 512 GB per process (why multi-level/hashed tables are needed)

== Effective access time (memory 100 ns, TLB 20 ns) ==
Without TLB (single-level table): 2 x 100 = 200 ns
TLB hit ratio 80%: EAT = 0.80*120 + 0.20*220 = 140.0 ns (slow-down vs 100 ns: 40.0%)
TLB hit ratio 95%: EAT = 0.95*120 + 0.05*220 = 125.0 ns (slow-down vs 100 ns: 25.0%)
TLB hit ratio 99%: EAT = 0.99*120 + 0.01*220 = 121.0 ns (slow-down vs 100 ns: 21.0%)

== Space comparison: 16 GB RAM, 4 KB pages, 100 processes each with 48-bit address space ==
inverted: 4194304 entries x 16 B = 64 MB total, independent of number of processes
per-process 4-level table, 4 KB table pages, if a process maps 100 MB densely: about 216 KB per process = 21.1 MB for 100 processes (grows with processes)
per-process worst case: the 2^36-entry flat table would need 512 GB each (impossible).
Time: inverted = hash + chain walk (~1-2 memory accesses, but no sharing of frames between processes and slow lookup by frame);
      4-level walk = 4 memory accesses on a TLB miss.
